# Security Review: Env Resolution and .portweave/current.env Writer

## Summary

**No high-confidence security vulnerabilities identified in this PR.**

The env-resolution layer is a pure-compute + local-filesystem path: it takes an already-validated `Config` and `Allocation`, computes a `{ envVar -> port }` map, optionally overlays Portweave-known keys from the user's own `.env`, and atomically writes `.portweave/current.env` into the user-owned project directory. All inputs are either trusted (config validated upstream, allocation produced internally) or the user's own files (trusted per the local-CLI threat model). There is no network surface, no shell invocation, no dynamic code construction, and no untrusted deserialization.

The merge is effectively a whitelisted overlay. |

No `eval`/`Function` constructor, no shell expansion, no recursive expansion of the substituted value.                                                                                                                                                                                                                                                                                                                                                         |

## Trust-model fit

Per the project's documented threat model:

- Environment variables and CLI flags are **trusted**.
- `portweave.config.json` is validated upstream by the config-loader (already reviewed).
- `.env` at the project root is the user's own file — the user is also the runner.
- All writes land in the user-owned project directory under `.portweave/`.

Every input this module consumes falls under one of those trusted sources, and every output lands inside a directory the user already owns. There is no remote attack surface and no privilege boundary being crossed.

## Verdict

**Pass — no high-confidence security vulnerabilities.**

The PR introduces sensible defensive hygiene (`Object.hasOwn` gates, `0o600`/`0o700` file modes, `wx` write flag for `.gitignore`, whitelisted dotenv overlay restricted to Portweave-known keys) and avoids every common pitfall in the categories above. No remediation required.
